# ADR-0015: Shared agent contract for the router modules (script/agent/contract.ts)

- Status: Accepted
- Date: 2026-11-06
- Related: issue #87 (T001), Epic #86, ADR-0014, config/agents.toml

## Context

Epic #86 extends the unified launcher (`script/agent.ts`) with route status,
capability catalogs, quota telemetry, usage ledgers, machine placement and
durable checkpoints, spread over child issues #88–#105. Without a shared
contract each module would invent its own identity spelling and its own
notion of "verified", and the epic's core safety property — unknown or stale
evidence must never be presented as available — would have to be re-implemented
(and re-got-wrong) per module.

`config/agents.toml` stays the single source of truth for providers, models,
credentials (names only) and routes (ADR-0014 §2). The contract must not
duplicate that data; it only defines the shapes and rules the derived
modules exchange.

## Decision

1. **One shared contract module: `script/agent/contract.ts`.** Pure Bun+TS,
   no dependencies, no I/O on config or credentials, no process launches.
   It never changes an existing launch path; `script/agent.ts` does not
   import it (the launcher keeps its own internal parsers).
2. **Versioned surface.** `CONTRACT_VERSION` (semver, currently `1.0.0`)
   travels in every JSON envelope producers emit; readers parse envelopes
   with `parseEnvelope` (unknown-field rejection + major-version check,
   `assertCompatibleVersion`) before interpreting foreign data. The exported
   surface is intentionally small: identity
   (`parseRouteId`/`formatRouteId`, `parseModelId`, `parseMachineId`,
   `formatAttemptKey`/`parseAttemptKey`, `resolveLegacyRouteRef`,
   `assertSameRoute`, `assertSameAttempt`),
   attestation (`Attested`, `attest`, `parseAttested`, `isUsable`,
   `requireUsable`, `isStale`, `DEFAULT_MAX_EVIDENCE_AGE_MS`), quota scope
   (`QuotaScope`, `quotaScopeKey`), redaction
   (`redact`, `redactJson`, `isSecretKeyName`, `looksLikeSecretValue`,
   `REDACTED`), canonical JSON
   (`toJson`, `parseJson`), schema helpers (`parseEnvelope`, `expectFields`,
   `requireStr`, `optionalStr`, `requireBool`, `optionalInt`, `stringList`)
   and the state root (`agentStateDir`).
3. **Identity rules mirror the launcher.** Route ids are
   `<harness>.<provider>`, split at the first dot only; legacy
   `<harness>-<provider>` names resolve by exact match against configured
   routes, never by splitting on hyphens, so `claude-openrouter-free` can
   never degrade to `claude.openrouter`; an ambiguous shortcut (two routes
   deriving one name) throws like the launcher's config-load check. Machine
   ids exclude dots so a machine id can never be mistaken for a route id;
   attempt keys (`route#model#machine#attempt`) re-validate every component
   with the same rules on parse as on format, so swapped or rebuilt
   identities fail closed. `assertSameRoute`/`assertSameAttempt` are the
   read-side guards: a record claimed under one route/attempt identity
   cannot be read as another.
4. **Attestation is the only path to "available" — on both paths.** Every
   provider/model/route fact that downstream modules publish is an
   `Attested<T>`: a value plus `status` (`configured` / `verified-live` /
   `restricted` / `unknown`), `provenance` (`measured` / `estimated` /
   `official`), evidence (timestamp, source, optional SHA) and, for
   restrictions, a persisted `note` with the reason. One matrix
   (`validateAttestation`) is enforced on the write path (`attest`) AND on
   the read path (`parseAttested`): `verified-live` requires observed live
   evidence (live-e2e/probe), `measured` provenance and a present value;
   `restricted` requires OBSERVED live evidence (published docs do not
   observe a restriction) plus a note; `unknown` carries no value and no
   evidence; measured claims require live evidence; official claims require
   provider-published evidence; `configured` may not borrow live evidence.
   `parseAttested` additionally rejects unknown fields, so a forged object
   read from disk or JSON (`{status:'verified-live', provenance:'estimated'}`
   or `value:null`) fails closed instead of being trusted.
5. **Usability is fail-closed and always freshness-bounded.**
   `isUsable`/`requireUsable` re-validate through `parseAttested` and accept
   only fresh `verified-live`. The freshness window defaults to
   `DEFAULT_MAX_EVIDENCE_AGE_MS` (7 days) and can be tightened but never
   removed — there is no unbounded mode. Evidence dated in the future beyond
   a 60s clock-skew allowance is invalid (`isStale` returns true), so a
   tampered timestamp can only make a fact less usable, never more.
6. **Quota scope separates accounts from machines.** A quota/usage fact
   names its allowance (`account` / `api-key` / `plan` / `machine`); the
   `api-key` scope's id is the Infisical secret NAME, never a value.
   Consumers dedupe by `quotaScopeKey`, so the same account allowance is
   never double-counted across machines.
7. **One canonical JSON.** `toJson` sorts keys recursively (stable bytes);
   `redactJson` = redact + `toJson` and is the required writer for anything
   persisted or logged. Redaction is name-based (`api_key`, `secret`,
   `*token*`, `*credential*`, snake_case and camelCase alike —
   `clientSecret`, `bearerToken`, `idToken`, `githubToken`) and value-based
   (strings shaped like `Bearer …`, `sk-…`, `ghp_…`, `AKIA…` credentials are
   redacted regardless of key name), while deliberately keeping usage
   counters such as `tokens_used` intact. Schema helpers reject unknown
   fields with the same fail-closed semantics as the launcher's own config
   parser.
8. **Non-secret local state root: `agentStateDir()`** —
   `$XDG_STATE_HOME/agent` (default `~/.local/state/agent`), overridable
   with `AGENT_STATE_DIR`. Only redacted/non-secret data may be written
   there, always through `redactJson`. Subpath ownership: capability/
   catalog state → #89, quota/reset → #91, usage ledger → #93, machine
   inventory → #97, attempts/checkpoints/fencing → #99. Durable project
   truth remains GitHub Issues/PRs/Git (Epic #86 §Non-negotiable 4); the
   state root is a cache, never a second source of truth.
9. **`config/agents.toml` schema extension proposal (NOT applied here).**
   The toml is owned by the Supervisor; this issue only proposes. When #89
   (catalog) lands, extend provider/model/route tables additively:
   - `[providers.X.models.Y]`-level or route-level `capability` tables
     (`tool_call`, `context`, `output`) — the existing
     `opencode_models` pattern generalizes;
   - per-fact attestation fields: `status`, `provenance`, `evidence_at`,
     `evidence_source`, `evidence_sha`, `evidence_note`;
   - per-route `quota_scope` (`kind` + `id`) naming the shared allowance.
   Rules: only secret NAMES ever appear; unknown keys keep failing closed;
   absent attestation fields mean `status = "configured"` with
   `provenance = "estimated"` — never silently `verified-live`. The
   existing `note` fields in `[routes.*]` are free text and stay; their
   facts (e.g. "verified 2026-11-01") should migrate into attested fields
   when #89 lands, so the launcher can enforce them instead of prose.

## Consequences

- Child issues #88–#94 and #96–#99 import from `script/agent/contract.ts`
  instead of redefining identity/evidence semantics; breaking its exported
  surface requires a major version bump and a coordinated change.
- Facts currently encoded as prose in `config/agents.toml` comments (live
  verification dates, 402/429 observations) become machine-checkable only
  after #89 adopts the extension above; until then the contract's
  `Attested` shape is available but the toml is not yet the source.
- Redaction is name-based and can under-redact a novel secret spelling;
  the primary defense remains "secret values never enter contract data"
  (Infisical injection at launch time, names only in config). `redactJson`
  is the second line, not the first.
- The contract module adds one more file under `script/agent/`, which so
  far held only provider shell wrappers; the directory now also hosts the
  router's shared TS modules (as anticipated by Epic #86's "small TS
  modules under `script/agent/`").

## Verification

- `bun test script/agent.contract.test.ts` — 53 tests covering schema
  validation, unknown-field rejection (envelope and attested), version
  compatibility, secret redaction (snake_case, camelCase, value shapes,
  shared refs, cycles, prototype safety), legacy route parsing incl.
  ambiguity (fixture + real `config/agents.toml`), forged-attestation
  fail-closed reads, freshness bounds and future-dated evidence, JSON
  roundtrip through the read path and identity-mixup negative tests. All
  pass on this commit's SHA.
- No existing test or launcher behavior changed: `script/agent.ts` and
  `config/agents.toml` are untouched by this ADR's implementation.
