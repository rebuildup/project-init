# ADR-0018: Merge-Commit-Only Pull Request Landing

- Status: Accepted
- Date: 2026-09-22
- Extends: ADR-0012, ADR-0016, ADR-0017
- Classification: Current release-driven Operating Model / Practice
- Superseded by: None

## Context

current release-driven profileでは、PRのauthorization boundaryは定義されている一方、authorized PRをどのGitHub merge methodでlandするかは固定されていなかった。

merge / squash merge / rebase mergeがrepositoryやexecutorごとに混在すると、同じdelivery modelでも履歴の意味が変わる。特にsquash mergeはPR内のcommit identityを統合時に失い、rebase mergeはPRを統合した境界を明示するmerge commitを残さない。

このprofileでは、PR内で積み上げたcommit履歴と「このPRをこのtargetへ統合した」という境界の両方をGit historyへ残すことを標準とする。

## Decision

### 1. Pull Request landing uses merge commits

current release-driven profileでGitHub Pull Requestをlandする場合、標準methodは **merge commit** のみとする。

- merge commit: 使用する
- squash merge: 使用しない
- rebase merge: 使用しない

ticket PR、stacked ticketのactual landing、release PRのいずれにも同じruleを適用する。

### 2. Repository merge settings are reconciled

initializer / readiness reviewはrepository merge settingsを確認し、設定変更権限がある場合は次へreconcileする。

```text
allow_merge_commit = true
allow_squash_merge = false
allow_rebase_merge = false
```

権限がなく設定を変更できない場合、期待設定との差分を黙認せずblockerまたは明示的platform/configuration limitationとして報告する。

### 3. Merge executors select `merge` explicitly

Agent / automation / release toolingがGitHub merge API等を呼ぶ場合、repository defaultへmethod選択を委ねず、merge commit method (`merge`) を明示する。

auto-mergeを利用する場合も、repository側でmerge commitだけが有効であることを確認する。methodを保証できないauto-merge pathは使用しない。

### 4. Branch-local rebase remains allowed

このdecisionが禁止するのはGitHub PRの **rebase merge** であり、作業branch自身を更新するための `git rebase` ではない。

stacked PRのpredecessor追従、conflict解消、branch maintenance等でbranch-local rebaseが必要な場合は、既存のauthorization / validation / force-push policyに従って使用できる。

### 5. Stacked landing must preserve the merge-method invariant

native stacked-PR landingや外部stack toolを利用する場合も、target release trunkへ実際にlandする各PRがmerge commit semanticsを保持する必要がある。

platform/toolがstack landingでsquashまたはrebase semanticsしか提供できない場合、そのlanding pathはcurrent profileでは使用せず、dependency orderに従ってmerge commitでlandする方法へfallbackする。

### 6. Merge authorization is unchanged

ADR-0012のexplicit user authorization boundaryは変更しない。

merge methodが固定されていること、repository settingsが正しいこと、CI/reviewがgreenであることはmerge authorizationの代替にならない。authorizationがない場合は従来通りready-to-mergeで停止する。

## Consequences

- PR内の個々のcommit identityを統合後も追跡できる。
- PR単位のintegration boundaryがmerge commitとしてGit historyへ残る。
- squash/rebase mergeによるrepositoryごとの履歴差異をなくせる。
- historyはlinearにはならずmerge commitが増える。
- commit hygieneの価値が高まり、意味のない途中commitを大量に残す運用は別途改善対象になる。
- stack toolingはmerge commit semanticsを満たす範囲でのみ利用できる。

## Verification

initializer / policy review / release readinessでは最低限次を確認する。

- repositoryでmerge commitが有効
- squash mergeが無効
- rebase mergeが無効
- Agent / automationのPR landingが`merge` methodを明示
- branch-local rebaseとPR rebase mergeを混同していない
- stacked landingがmerge commit semanticsを維持
- explicit merge authorization invariantが維持されている
