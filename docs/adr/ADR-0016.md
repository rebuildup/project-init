# ADR-0016: Durable attempts, generation fencing, checkpoints and the side-effect journal

- Status: Accepted
- Date: 2026-11-06
- Related: ADR-0015 (shared contract), Epic #86, issue #99 (T013), issues #98/#100/#101 (consumers)

## Context

Epic #86 workers run on fallible machines and fallible providers. Recovery
(#101) and dispatch (#100) need durable facts about what an attempt was doing:
what it started from, what it declared, what completed. Herdr panes and
provider sessions are explicitly NOT recovery sources (Epic #86 non-negotiable
3: pane state ≠ completion). The launcher's existing local state root
(`agentStateDir()`, ADR-0015 §8) reserves `attempts/` and `checkpoints/` for
this module.

## Decision

1. **One attempt record per attempt key**, stored as
   `<agentStateDir>/attempts/<sha256(key)>.json`-keyed directories holding
   `record.json` and one `lease-<generation>.json` per generation. The
   sha256 name keeps hostile/long keys out of path lengths; the key itself is
   re-validated with `parseAttemptKey` on every read.
2. **Fencing = generation files, created with O_EXCL.** Acquiring generation
   N+1 is an exclusive create of `lease-<N+1>.json`; a stale worker is any
   holder of generation ≤ N. `assertLeaseCurrent` gates every write path
   (results, children, side-effect posts) and compares the caller's lease
   against the STORED lease (owner, acquiredAt, released) — a forged or
   stale in-memory lease cannot pass. Record updates are generation-CAS:
   `updateRecord` refuses when the record's generation moved.
3. **Parent/child independence.** Children are separate records linked by
   key (`parent`, `children` fields). Fencing or losing a parent never
   touches child records — child state survives parent death and is
   recoverable on its own.
4. **Checkpoints distinguish soft from hard.** A SOFT checkpoint lives only
   in `agentStateDir()/checkpoints` and may be lost with the machine. A HARD
   checkpoint carries a `DurableRef` (GitHub issue/PR/git ref + https URL)
   that recovery can fetch back. Both are the same strict schema
   (`parseCheckpoint`); only the presence of a durable reference differs.
   Checkpoint files are byte-stable (sorted keys) and never contain
   secret-shaped data.
5. **Side-effect journal: pre/post, append-only JSONL.** An external write is
   declared with `journalPreEffect` BEFORE it happens and completed with
   `journalPostEffect` afterwards. A pre without a post is an effect whose
   outcome is UNKNOWN — recovery must verify externally, never assume it did
   not happen. Posts are only accepted from the current generation, so a
   fenced worker cannot complete effects; a NEWER generation may complete an
   OLDER generation's declared effect (the recovery path). Effects declared
   under a newer generation than the poster's are refused.
6. **Fail-closed everywhere.** Timestamps are ISO 8601 UTC strings (epoch
   numbers rejected); generations are bounded integers; owner labels are
   non-secret slugs; secret-shaped keys or values are refused at the write
   boundary (`assertNoSecrets`), never silently redacted into durable state.

## Consequences

- Recovery (#101) composes: acquire next generation → read checkpoint →
  reconcile `pendingSideEffects` → resume or fence. It never needs the dead
  worker's memory or session.
- The journal is a cache of INTENT, not truth: an unknown-outcome effect must
  be verified against the outside world (git ls-remote, GitHub API) before
  being assumed done or not done.
- `script/agent.ts` (Supervisor-owned) is untouched; consumers import the
  modules; integration lands in #100/#101/#102.
- Windows/WSL real-machine behavior is #105's evidence obligation; the
  two-process lease race is proven on POSIX here (O_EXCL is POSIX semantics).

## Verification

- `bun test script/agent.attempts.test.ts` — 43 tests: double-lease CAS
  (in-process and two real processes), stale-result rejection, parent-death
  child survival, hostile input matrix (NaN/infinity/epoch/self-parent),
  soft/hard checkpoint round-trips, GitHub-durable restore, journal
  pre/post/recovery, and byte-level secret-free checks of persisted state.
