# ADR-0010: Evidence-Based AI Agent Delivery Forecasting

- Status: Accepted
- Date: 2026-09-14
- Extends: ADR-0003, ADR-0005, ADR-0007, ADR-0008
- Superseded by: None

## Context

AI coding agents can produce plausible calendar estimates without grounding them in the actual project. In multi-agent development, wall-clock delivery also depends on dependency structure, parallel execution, model/provider usage limits, CI, human review/decisions, external waits, retries, and rework.

The repository already defines weekly release cadence, isolated parallel execution, quality gates, and recovery semantics. It did not define how medium/long-term completion dates or capacity claims should be derived from those systems.

## Decision

Introduce `skills/agent-delivery-estimation/SKILL.md` as the canonical progressive-disclosure policy for medium/long-term delivery forecasting.

The policy requires:

- relative Work Units and a dependency graph before calendar estimation
- project-local anchor calibration for Work Unit weights
- observed throughput and explicit provenance for numerical inputs
- separate treatment of agent capacity, human capacity, CI/internal queue, external wait, and usage limits
- no linear agent-count speedup assumption without controlled evidence
- risk-to-rework/block/delay mapping when historical evidence exists
- explicit unknown handling with `complete / conditional / unavailable`
- empirical bootstrap resampling when sample quality is sufficient
- sample-size quality tiers before publishing P50/P80/P95
- persistence and recalibration of observations/forecasts when appropriate

A one-week sprint remains the normal planning cadence from ADR-0008. It is not evidence that selected scope completes in one week.

The estimation policy must not weaken execution isolation, recovery fencing, quality gates, or release gates to make a forecast appear achievable.

## Integration

- `github-delivery` uses this Skill for release/roadmap dates, scope/capacity, and carry-over decisions.
- `parallel-orchestration` exposes active-agent/WIP/blocking/resource observations and uses the Skill before schedule-driven scaling claims.
- `quality-gate` exposes validation/CI wait and retry observations while remaining authoritative about required verification.
- initialization prompts contain only Skill-selection/invariant rules; detailed estimation mechanics remain in the Skill for progressive disclosure.

## Consequences

Positive:

- plans are grounded in observed delivery behavior rather than model intuition
- human review, waiting, and usage limits become visible bottlenecks
- agent-scaling claims can be tested instead of assumed
- forecasts become recalibratable and auditable

Trade-offs:

- new projects may correctly return insufficient data rather than a convenient date
- probability forecasts require enough observations
- calibrated Work Units and observation data add small planning overhead
- cross-project estimates are intentionally weaker than within-project calibration

## Revisit when

Revisit if the repository adopts a stronger externally validated forecasting model, changes the canonical planning unit, or gains reliable provider-native capacity/forecast telemetry that supersedes this policy.
