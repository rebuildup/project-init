# ADR-0028: 初期化promptをroutingに縮約し、英語版を廃止する

- Status: Accepted
- Date: 2026-10-17
- Related: ADR-0001, ADR-0002
- Revises: ADR-0002（full promptの対象を `PROMPT.ja.md` の1本にする）
- Supersedes: None
- Superseded by: None

## Context

`PROMPT.ja.md`（約79KB）と `PROMPT.en.md`（約73KB）は同じ意味を並行して保守していた。英語版は実運用で使われておらず、変更のたびに意味がずれる余地だけが残っていた。

`PROMPT.ja.md` の内容の大半は、`organization/profiles/release-driven-solo.md` と各Skillに同等のcontractがあった。同じruleが prompt・profile・Skill・CONTRIBUTING・ADR に重複し、どれが正本か分かりにくく、片方だけ更新されるdriftの原因になっていた。2026-09-09のlost-rule auditは、この重複の中でruleが弱まったことを検出したものでもある。

`evals/policy-evaluation/*-contract.sh` はprompt本文の文言を直接検査しており、重複を固定化する方向に働いていた。

## Decision

1. 初期化promptは `PROMPT.ja.md` の1本だけにする。`PROMPT.en.md` は削除する。
2. `PROMPT.ja.md` が持つのは、調査 → 差分reconcile → 反映先の対応表 → root contractの生成 → 完了確認 という初期化手順と、正本へのroutingだけにする。ruleの中身は書き写さない。
3. ruleの正本は Constitution / profile / Skill とする。promptから外したruleのうち正本がなかったものは、次へ移した。
   - 同じfileを触ること自体は直列化の理由にならない → `parallel-orchestration` の Fallback
   - Reviewerが確認する観点（runtime再現性、PR metadata / Issue linkage、recovery / checkpoint整合を含む） → `parallel-orchestration` の Review handoff
   - 要求scopeを独断で縮めない、compile成功を完了としない → `engineering-decisions` §5
   - policy semanticsをplatformのpreview featureに依存させない → `github-delivery`
   - spawnの深さと数の上限 → `parallel-orchestration` の spawn contract
   - runtime / provider比較時のsnapshot永続性・suspend / resume・provider喪失時の復旧 → `sandbox-runtime` の Refinement criteria
   - CIの有無に応じたrelease PRのevidence → `github-delivery` の Release integration
   - 言語、Bun、`rg`、`.py` script禁止、TypeScript script、`Containerfile` → promptの House rule（初期化時にroot contractへ転記する）
4. contract evalは正本（profile / Skill / ADR）を検査する。promptについては正本へroutingしていることだけを検査する。

移行の監査結果は `docs/audits/2026-10-17-prompt-routing-audit.md` にある。

## Consequences

- promptは約79KBから約8.5KBになり、英語版の同期作業がなくなる。
- ruleを変更する時に更新するのは正本だけでよくなる。promptを変更するのは、正本の追加や初期化手順の変更がある時に限られる。
- 初期化agentは、promptだけでなくprofileとSkillを読む必要がある。これはprogressive disclosure（ADR-0001）の方針と一致する。
- `docs/roles/CODEX_ROLES.*.md` の日英並行は、このADRの対象外である。

## Re-evaluate / remove

英語話者のcontributorや、英語promptを必要とするagent runtimeが実際に現れたら、正本からの生成などduplicationを増やさない方法で再検討する。
