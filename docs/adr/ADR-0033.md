# ADR-0033: 反復テスト実行の適応的スケジューリング

- 状態: Accepted (Practice)
- 日付: 2026-10-26

## 判断

テストの実行要否を検証要求の性質と入力状態から決定する。required gateの確実性を維持したまま、開発ループ内の任意・反復テストに限り、同一入力・同一環境の連続成功から実行間隔を延長できる。

優先順位は既存ランナーの差分実行・結果キャッシュ、maintained ecosystem tool、それでも足りない場合の外付けスケジューラーとする。templates/quality/ の実装は最後の選択肢に対する参照であり、全リポジトリへの導入を強制しない。

## 保持する不変条件

- 現在のcandidateに必要な検証を省略された過去の成功で代替しない。延期（deferred）と検証成功（verified）は異なる結果として扱う。
- PR/ticket integration、release、security、compatibility、native/device/GUI等のrequired verificationでは実行間隔の減衰を根拠にゲートを省略しない。
- テストの入力・依存・環境が追跡できない場合は実行に倒す。履歴の欠損・破損も実行に倒す。
- 状態はworkerのmutable ownershipに閉じ、異なるworktree/環境での無検証共有を禁止する。
- プロジェクト固有のrisk、既存test toolingと観測コストを評価してopt-inとする。初期化時/再整備時に選び直す。

## 位置付け

品質検証レベルとentry pointの正本は引き続き skills/quality-gate/SKILL.md である。tool-independentなEvidenceの不変条件はConstitution側に保持し、実行間隔の数値や具体CLIをConstitutionへ昇格させない。

検証実行回数・所要時間・失敗検出率・誤った延期の有無を測定して再評価し、基準を満たせない場合は延期を停止する。
