# ADR-0030: writing-disciplineをwriting-skillsへ一本化し、導入した複製をhashで検査する

- Status: Accepted
- Date: 2026-10-17
- Related: ADR-0029
- Revises: ADR-0029（`writing-discipline` の担当をrebuildup/writing-skillsへ移す）
- Supersedes: None
- Superseded by: None

## Context

`writing-discipline` は、project-initとrebuildup/writing-skillsの両方にあり、内容がずれていた。project-initに置いていたのは、どのprojectでも必ず参照される基盤だと考えていたためである。しかし複製が2つあると、片方だけが更新され、どちらが正しいか分からなくなる。

参照を確実にするには、ファイルの置き場所ではなく、次の3つが効く。

- 初期化時に必ず導入されること
- root contractから必ずroutingされること
- 導入した複製が勝手に書き換えられないこと

## Decision

1. `writing-discipline` の正本はrebuildup/writing-skillsとする。graderとfixturesもそちらへ移す（writing-skills#32）。
2. project-initは `skills/writing-discipline` を削除する。project-init自身の作業用には、writing-skillsから `--copy` で `.claude/skills/` へ導入し、`skills-lock.json` と一緒にcommitする。`skills add <source> --list` はこの複製を公開対象として数えないことを確認した。
3. 導入した複製の内容がlockの `computedHash` と一致することを `vendored-skills-contract.sh` で検査する。hashは、`skills` CLIと同じく、各fileの相対pathと中身をpathの大文字小文字を区別しない順に連結したsha256である。直接編集すると検査が落ちるので、変更は正本へのPRと `skills update` を通す。
4. `needed_when` が `always` の能力には、必ず `default` の担当があることを `skill-catalog-contract.sh` で検査する。`prose-artifact` はこの対象であり、どのprojectにも `writing-discipline` が導入される。
5. Skillはガードレールとして選ぶ。発火場面にちょうど当てはまり、手順の量が防ぐ失敗に見合うものだけを採る。この基準を `skill-selection` に書く。

## Consequences

- `writing-discipline` の変更はwriting-skillsだけで行い、project-initには `skills update` のdiffとして届く。
- lockの `ref` は、正本のPRがmergeされるまでticket branch（`32`）を指す。merge後に、release branchかtagへ付け替える必要がある。`ref` にcommit SHAは使えない。
- interaction-disciplineなど、project-init内の他のSkillからの `writing-discipline` への言及は、名前による参照のまま変わらない。
